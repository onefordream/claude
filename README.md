# ゴルフスクール向け 成長AI記録ノート・テンプレート

生徒が毎回のレッスン・練習後に自分で内容を書き残す「成長ノート」アプリです。
書いた記録はAIが自動で要約し、次回の課題を整理します。生徒はいつでも履歴を振り返ったり、
AIコーチに「今日は何を練習すべきか」を相談できます。ラウンド結果(コース・スコア・課題)や
目標設定、指導者が用意するレッスン動画ライブラリも備え、指導者は管理画面から
全生徒の記録を横断的に確認できます。

**このリポジトリは、店舗ごとに1つずつデプロイして販売する「テンプレート」として作られています。**
店舗間でデータベースを共有することはなく、店舗ごとに個別のRenderサービス・データベースを
用意します。店舗の見た目(店舗名・ロゴ・配色)は設定だけで変えられるようになっているため、
新しい店舗向けに作るたびにアプリのコードを書き換える必要はありません。

このREADMEは、**新しい店舗にこのサービスを導入するときの実際の手順書**として使うことを
想定しています。導入手順は「新しい店舗に導入する」の章を参照してください。

---

## 主な機能

- **生徒**
  - レッスン・自主練の内容を自分で入力して記録として保存(日付・内容・気づきメモ、自主練は時間/球数も)
  - 練習動画の添付・保存・再生(複数可)
  - AIによる自動要約 + 次回の課題の抽出
  - 「今日の練習メニュー」をAIコーチに相談(直近のレッスン履歴・ラウンド履歴を踏まえて提案)
  - ラウンド記録(日付・コース名・スコア・パター数・気づいた課題・メモ)、ベストスコア/平均スコアの
    スタッツとスコア推移グラフ
  - 目標設定(達成期限つき)。ダッシュボードに常時表示され、達成したら次の目標を設定できる
  - 指導者が用意したレッスン動画をいつでも見返せる動画ライブラリ
  - 自分のゴルフライフ全体を振り返れるダッシュボード
- **指導者(管理者)**
  - 生徒一覧(名前・フリガナで検索可、記録件数・最終レッスン日)
  - 各生徒の成長ノート・AI要約・ラウンド履歴・目標を横断的に閲覧
  - 生徒がパスワードを忘れた場合に、その場で新しいパスワードを発行(管理画面から)
  - 複数の指導者アカウントを作成・管理(指導者が増えても1アカウントずつ追加できる)
  - レッスン動画ライブラリの管理(アップロード・削除)
  - 全データ(生徒・記録・ラウンド・目標)をJSONファイルとして書き出し、バックアップ・移行に利用
- **その他**
  - ログイン試行・新規登録のレート制限、推測されにくいセッション管理など基本的なセキュリティ対策
  - 利用規約・プライバシーポリシーのページ(店舗ごとに内容を見直して利用するひな形)

## 新しい店舗に導入する

**前提:** 1店舗につき1つのGitHubブランチ + 1つのRenderサービス + 1つのデータベースを作ります。
店舗間でデータは一切共有されません。ロゴ画像はコードの一部として管理しているため、店舗ごとに
コードのコピー(ブランチ)を分ける必要があります。

### 1. その店舗専用のブランチを作る

1. GitHub上でこのリポジトリ(`onefordream/claude`)を開く
2. 既存のブランチ(例: `claude/golf-lesson-ai-system-yb0k0m`)から、新しい店舗用のブランチを
   作成する(例: `store/tokyo-golf-lab`)
3. そのブランチ上で `public/logo.png` を、その店舗のロゴ画像に置き換える(ファイル名は
   `logo.png` のまま。GitHubのWeb UIから既存ファイルを削除→同名でアップロードすればよい)

### 2. Renderで新しいWebサービスを作る

1. [Render](https://dashboard.render.com) にログイン
2. 「New +」→「Web Service」
3. このGitHubリポジトリを接続し、**手順1で作った店舗専用ブランチ**を選択
4. 以下を設定
   - **Name**: 店舗名が分かる名前(例: `tokyo-golf-lab-growth-note`)
   - **Runtime**: Node
   - **Build Command**: 空欄のままでよい(npm依存パッケージを使っていないため)
   - **Start Command**: `npm start`
   - **Instance Type**: **Starter以上の有料プラン**を選択(理由は次の「運用上の重要な注意」を参照)

### 3. 永続ディスクを追加する(必須)

Render Freeプランや、ディスクを追加していない有料プランでは、**再デプロイのたびにデータベースと
アップロードされた動画が消えます。** 必ず以下を行ってください。

1. 作成したサービスの「Settings」→「Disks」→「Add Disk」
2. **Mount Path**: `/var/data`
3. サイズは生徒数・動画の利用量に応じて選択(動画をよく使う場合は余裕を持ったサイズに)

### 4. 環境変数を設定する

「Settings」→「Environment」で以下を設定します。

| 変数名 | 内容 | 例 |
|---|---|---|
| `SESSION_SECRET` | セッション署名用の秘密鍵。Renderの「Generate」機能でランダム生成してよい | (ランダム文字列) |
| `STUDIO_NAME` | 店舗名(画面上部・タイトルに表示) | `TOKYO GOLF LAB` |
| `APP_TAGLINE` | キャッチコピー(ログイン画面の見出し下) | `スイング上達ノート` |
| `BRAND_COLOR` | メインカラー(HEX)。ボタン・ナビ等の配色一式が自動生成される | `#1e3a8a` |
| `OWNER_NAME` | 最初に作成される指導者アカウントの名前 | `東京代表` |
| `OWNER_EMAIL` | 最初の指導者アカウントのログインメールアドレス | `owner@example.com` |
| `OWNER_PASSWORD` | 最初の指導者アカウントのパスワード(**仮パスワードを設定し、初回ログイン後に伝える**) | — |
| `ANTHROPIC_API_KEY` | AI要約・提案機能を使う場合に設定(未設定でも他機能は動作する) | — |
| `ANTHROPIC_MODEL` | 使用するAIモデル | `claude-sonnet-5` |
| `DATA_DIR` | **手順3で追加した永続ディスクのMount Pathと同じ値を指定** | `/var/data` |

### 5. デプロイ・動作確認

1. 「Manual Deploy」→「Deploy latest commit」でデプロイを実行
2. デプロイ完了後、発行されたURLにアクセスし、`OWNER_EMAIL`/`OWNER_PASSWORD` でログインできることを確認
3. ロゴ・店舗名・配色が正しく反映されているか確認
4. 必要であれば「指導者管理」画面から追加の指導者アカウントを発行する

### 6. 店舗への引き渡し

- 発行されたURL、最初の指導者ログイン情報を店舗側に伝える
- 生徒登録は `/register` から生徒自身が行う(指導者アカウントは発行制のため、生徒登録フォームからは作成されない)
- 利用規約・プライバシーポリシー(`/terms` ・ `/privacy`)は**ひな形**なので、実際の運用前に
  店舗側(できれば専門家)に内容を確認してもらうことを推奨

## 運用上の重要な注意

これらは実際の顧客データを預かる前に必ず確認・対応してください。

1. **永続ディスク(`DATA_DIR`)を必ず設定する** — 設定していない場合、再デプロイ(コード更新・
   Renderの再起動)のたびにデータベースとアップロード済み動画がすべて消えます。店舗ごとに
   「Disks」タブで実際に追加されているか確認してください。
2. **自動デプロイがオフになっている場合がある** — Renderの設定によっては、GitHubにコードを
   push しても自動では反映されず、「Manual Deploy」→「Deploy latest commit」を手動で押す
   必要があります。コードを更新したら、各店舗のRenderサービスで確認してください。
3. **バックアップを定期的に取る** — 管理画面の「全データをエクスポート」から、生徒・記録・
   ラウンド・目標をJSONで書き出せます。永続ディスクがあっても、Renderのディスク障害や誤操作に
   備えて定期的にダウンロードしておくことを推奨します(動画ファイル自体はこのエクスポートに
   含まれないため、重要な動画は別途保管してください)。
4. **想定規模** — 現在の構成は、1店舗あたり数十〜数百人規模の生徒を想定した構成です
   (単一プロセス・SQLite・ローカルディスク保存)。1店舗で利用者が急増する場合や、動画の
   同時アップロードが非常に多い場合は、データベース(PostgreSQL等)や動画ストレージ(S3等)
   への移行を検討してください。

## 技術的な注意点

この開発環境では **npmレジストリへの外部アクセスがブロック**されていたため
(`registry.npmjs.org` への接続が組織ポリシーにより403で拒否)、Next.js・Prisma・
Anthropic公式SDKなどの外部パッケージを一切インストールできませんでした。

そのため本アプリは **npm依存パッケージ0** で、Node.js 22 の標準機能のみで実装しています。

| 領域 | 使用技術 |
|---|---|
| サーバー | `node:http`(自前の軽量ルーター) |
| データベース | `node:sqlite`(Node.js組み込み、実験的機能) |
| 認証 | `node:crypto`(scryptによるパスワードハッシュ、セッショントークン+DBセッション管理) |
| ファイルアップロード | 自前のmultipart/form-dataパーサー |
| AI連携 | Anthropic Messages API を `fetch` で直接呼び出し(SDK不使用) |
| フロント | サーバーサイドレンダリングのHTML + 最小限のvanilla JS |

`node:sqlite` は実験的機能のため起動時に `ExperimentalWarning` が表示されますが、動作には
問題ありません。

### セキュリティ対策

- パスワードは scrypt でハッシュ化して保存(平文保存なし)
- SQLはすべてパラメータ化クエリ(SQLインジェクション対策)
- ログイン試行(メールアドレス単位)・新規登録(IPアドレス単位)にレート制限
- セッションCookieは `HttpOnly` + `SameSite=Lax`、Render上では `Secure` 属性も付与
- アップロードファイルはランダムなファイル名で保存し、パストラバーサル対策済み
- フォーム送信のボディサイズに上限を設け、意図的な大容量リクエストによる負荷を防止

## ローカルでの開発・動作確認

```bash
# 1. .env を作成
cp .env.example .env

# 2. .env を編集
#    - OWNER_EMAIL / OWNER_PASSWORD : 最初に自動作成される指導者(オーナー)アカウント
#    - ANTHROPIC_API_KEY            : AI要約・提案機能を使う場合は設定(未設定でもアプリ自体は動作します)

# 3. 起動
npm start
# もしくは開発中はファイル変更を自動反映する
npm run dev
```

起動すると `http://localhost:3000` でアクセスできます。初回起動時に `.env` の
`OWNER_EMAIL` / `OWNER_PASSWORD` で指導者アカウントが自動的に作成されます。

### デモデータの投入(任意)

サンプルの生徒アカウントと過去のレッスン・ラウンド記録を投入できます。

```bash
npm run seed
```

- メール: `demo.student@example.com`
- パスワード: `password123`

### AI機能について

`ANTHROPIC_API_KEY` を設定すると以下が有効になります。

- レッスンカルテ保存時に自動でAI要約 + 次回の課題を生成(バックグラウンド処理、保存直後は
  「要約待ち」と表示され、数秒後に反映されます)
- ダッシュボードの「今日の練習メニューを聞く」ボタンから、直近の記録を踏まえた練習提案を取得

未設定の場合はエラーにならず、「AI機能は未設定です」と表示されて他の機能は通常通り使えます。

## ディレクトリ構成

```
server.js             エントリーポイント・ルーティング
src/config.js         店舗ブランディング設定(店舗名・タグライン・配色)
src/db.js             node:sqlite セットアップ・スキーマ
src/auth.js           認証・セッション・パスワード管理
src/lib/ai.js          Anthropic API 連携
src/lib/multipart.js   ファイルアップロード用パーサー
src/lib/http.js        リクエスト/レスポンス補助関数
src/lib/rateLimit.js   ログイン・登録のレート制限
src/lib/env.js         .env ローダー
src/lib/date.js        JST(日本時間)基準の日付処理
src/views/             HTMLテンプレート(サーバーサイドレンダリング)
src/views/legal.js     利用規約・プライバシーポリシーのひな形
public/logo.png        店舗ロゴ(店舗ごとに差し替え対象)
public/                CSS・クライアントJS(静的配信)
scripts/seed.js        デモデータ投入スクリプト
uploads/               アップロードされた動画の保存先(gitignore対象)
data/                  SQLiteファイルの保存先(gitignore対象)
```
